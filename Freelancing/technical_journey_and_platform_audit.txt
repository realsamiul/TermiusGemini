### PART 2: NAVIGATED CHALLENGES AND ISSUES

The development and deployment process encountered several significant hurdles, requiring precise interventions to maintain project integrity and leverage GCP platform capabilities effectively:

1.  **Python 3.14 Pydantic Rust-Bindings Compilation Crash**:
    *   **Problem**: The VM's Python 3.14 environment caused compilation failures for older `pydantic-core` Rust bindings due to removed C-API macros.
    *   **Resolution**: Updated `google-cloud-aiplatform` and forced-installed `vertexai` with `--no-deps` to utilize pre-compiled wheels.

2.  **Vertex AI RAG Spanner Capacity Restrictions**:
    *   **Problem**: Default Vertex AI RAG corpora creation in `us-central1` failed due to Spanner capacity limits, requiring specific project allowlisting or Serverless mode.
    *   **Resolution**: Bypassed SDK limitations by using a direct REST `PATCH` request to switch the project's RAG Engine to **Serverless Mode** (`ragManagedDbConfig: { serverless: {} }`).

3.  **Vertex AI SDK Type Mismatch & Deserialization Issues**:
    *   **Problem**: Several critical SDK components (`RagEmbeddingModelConfig`, `retrieval_query_async`, `metadata_filters`) exhibited serialization bugs and deprecations. Specifically, `rag.py` expected `RagEmbeddingModelConfig` but the internal GAPIC layer looked for `publisher_model`, and `retrieval_query_async` was unavailable. Discovery Engine search results also returned `MapComposite` objects that were not deserializing correctly.
    *   **Resolution**:
        *   For embedding config: Instantiated `EmbeddingModelConfig` directly.
        *   For retrieval: Rewrote `rag.py` to use synchronous `client.search()` via `run_in_executor` and normalized Discovery Engine `SearchResult` objects into a `SearchChunk` class to handle `derived_struct_data` mapping (e.g., `extractive_segments`, `snippets`).

4.  **Cloud Build IAM Permissions for Source Deployment**:
    *   **Problem**: Cloud Run deployment via source failed due to the default compute service account lacking necessary IAM roles (`storage.admin`, `logging.logWriter`, `artifactregistry.writer`) for staging and publishing container images.
    *   **Resolution**: Programmatically granted these specific IAM roles to the compute service account at the project level.

5.  **Modal Token Initialization Crash**:
    *   **Problem**: FastAPI application crashed on boot due to attempting to write tokens directly to `modal.config._profile`, which Modern Modal SDKs treat as read-only.
    *   **Resolution**: Removed manual assignments. Modal SDK now natively loads tokens from environment variables configured in Cloud Run secrets.

6.  **Vertex AI Prediction 404 Model Access Lock**:
    *   **Problem**: Calls to standard Vertex AI Gemini models (`gemini-1.5-flash`, `gemini-1.5-pro`, etc.) in `us-central1` returned `404 NOT_FOUND` due to Model Garden access restrictions requiring manual term acceptance in the GCP console.
    *   **Resolution**: Switched to stable `gemini-3.5-flash` model and initialized in the `global` region, as confirmed to be accessible without console interaction. The primary backend services were updated to use these validated models.

7.  **Discovery Engine `data_schema` Mismatch for Raw PDFs**:
    *   **Problem**: Importing raw PDF files into standard search data stores failed with `"invalid unstructured data format"` error.
    *   **Resolution**: Modified `ingest_discovery.py` to explicitly set `data_schema="content"` in `GcsSource`, instructing Discovery Engine to parse files as raw unstructured documents.

8.  **Discovery Engine `projects:provision` Payload & Auth Issues**:
    *   **Problem**: Provisioning the project to Enterprise tier failed due to incorrect JSON payload (deprecated `edition`, `acceptServiceTerms`) and `403 PERMISSION_DENIED` due to missing `x-goog-user-project` header for ADC billing routing.
    *   **Resolution**: Updated `provision_discovery_enterprise.py` with the correct JSON payload (`"acceptDataUseTerms": true`, `"dataUseTermsVersion": "2022-11-23"`) and added the critical `x-goog-user-project` header for authentication.

### PART 3: DEPLOYED APPLICATIONS OVERVIEW & CAPABILITIES

We have successfully deployed two core applications, leveraging the cost-saving serverless architecture and the $1,000 GenAI App Builder credits:

**A. DocRAG-Legal V2 (Enterprise Compliance Auditor)**

*   **Deployment Target**: Google Cloud Run
*   **Core Technology Stack**: Python 3.14, FastAPI, Uvicorn, Discovery Engine (Search API), Gemini 1.5/3.5 Flash, Modal Persistence, GCP Secret Manager.
*   **Key Capabilities**:
    *   **Automated Compliance Auditing**:
        *   `/risk` Endpoint: Analyzes raw clauses against legal statutes, identifies conflicts, gaps, and provides risk scores.
        *   `/redline` Endpoint: Generates verbatim, compliant rewrites of clauses, outputting risk delta.
    *   **Grounded RAG Search & Synthesis**:
        *   `/query` Endpoint: Queries specialized Discovery Engine search stores (Statutes, IT Security, Clinical Safety) for semantically relevant document chunks.
        *   Gemini 1.5/3.5 synthesis provides answers grounded in context.
    *   **Adversarial Self-Audit & Verification**: The `eval_judge.py` module runs a critic loop on every AI response, scoring faithfulness, checking citations, and performing adversarial challenges to ensure answer integrity.
    *   **Cryptographic Provenance Chaining**: All session interactions are logged to a serverless Modal Ndjson volume and chained with SHA256 hashes, ensuring an immutable, tamper-evident audit trail.
    *   **Enterprise Security Headers**: Deployed with `Strict-Transport-Security`, `X-Content-Type-Options`, `X-Frame-Options`, `X-XSS-Protection`, and `Referrer-Policy` to ensure secure browser access.

**B. Erudite V2 (Empathetic Admissions Counselor)**

*   **Deployment Target**: Google Cloud Run
*   **Core Technology Stack**: Python 3.14, FastAPI, Discovery Engine (Search API), Gemini 3.5 Flash, Modal Persistence.
*   **Key Capabilities**:
    *   **High-Nuance RAG & Contextual Grounding**: Leverages Discovery Engine to parse aggregate data against specific South Asian/Bangladeshi contextual overlays, providing nuanced financial aid and admissions insights.
    *   **Fact-Based Myth Busting**: The Gemini synthesis layer (via system preamble) is engineered to authoritatively deconstruct systemic misconceptions (e.g., asymmetric risk of elite applications vs. safe schools) using provided data.
    *   **Scannable, High-Fidelity UI Presentation**: The backend outputs structured JSON payloads that the frontend dynamically renders into calming visual components (cards, charts, accordions) rather than walls of text.
    *   **Persona-Driven Guidance**: Employs a compassionate, realistic "older sibling" tone, providing tailored advice.
