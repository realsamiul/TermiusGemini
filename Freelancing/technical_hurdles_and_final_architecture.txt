1. CHRONOLOGICAL LOG OF ALL ENCOUNTERED HURDLES & RESOLUTIONS
--------------------------------------------------------------------------------

A. Python 3.14 + Pydantic rust-bindings compilation failure
   - The Hurdle: The VM was configured with pre-release Python 3.14. High-frequency 
     packages (like `firebase-admin` or local test packages) requested older pins 
     like `pydantic==2.8.2`, which triggered compilation of `pydantic-core` from 
     source. The Rust build compiler attempted to use legacy C-API Unicode macros 
     (e.g. `PyUnicode_New`) which have been completely removed in Python 3.14, 
     causing compilation crashes.
   - The Resolution: Upgraded `google-cloud-aiplatform` to `1.154.0` and forced-installed 
     the modern `vertexai==1.71.1` wrapper package without dependency backtracking 
     using `pip install vertexai==1.71.1 --no-deps`.

B. Vertex AI RAG Spanner capacity restrictions in us-central1
   - The Hurdle: Creating a standard Vertex RAG corpus with `RagManagedVertexVectorSearch()`
     automatically provisions a Cloud Spanner instance behind the scenes. For new 
     or standard billing accounts, Google restricts Spanner-backed RAG Engine 
     creation in major US regions (e.g. `us-central1`, `us-east1`, `us-east4`) due to 
     global capacity constraints, throwing a `400 INVALID_ARGUMENT` quota block.
   - The Resolution: We bypassed Google's python SDK limitations by writing and running 
     `scripts/patch_rag_config.py` to send a direct REST `PATCH` request to the 
     `v1beta1` management endpoint (`/ragEngineConfig`), successfully upgrading 
     the project's default RAG config to Serverless Mode.

C. Google Vertex AI Python SDK internal type mismatch
   - The Hurdle: The official Python SDK's `RagVectorDbConfig` class type-hints its 
     embedding field as requiring `RagEmbeddingModelConfig`. However, the SDK's 
     internal GAPIC serialization layer in `_gapic_utils.py` actually attempts to 
     access `.publisher_model` directly from it, expecting `EmbeddingModelConfig`, 
     resulting in a fatal `AttributeError: 'RagEmbeddingModelConfig' object has no 
     attribute 'publisher_model'` during corpus creation.
   - The Resolution: Leveraging Python's dynamic typing, we bypassed this SDK bug by 
     instantiating `EmbeddingModelConfig` and passing it directly into the 
     `rag_embedding_model_config` field of `RagVectorDbConfig` at runtime.

D. Cloud Build storage staging & Artifact Registry IAM permissions
   - The Hurdle: Deploying the container from local source directories failed on 
     the first run because the project's default Compute Engine service account 
     (`719705716921-compute@developer.gserviceaccount.com`) lacked read/write permissions 
     on the Cloud Run build source storage bucket and lacked pushing permissions for 
     the newly provisioned Artifact Registry directory.
   - The Resolution: We bound the target roles `roles/storage.admin`, `roles/logging.logWriter`, 
     and `roles/artifactregistry.writer` to the compute service account at the project level.

E. Modal Token string initialization crash
   - The Hurdle: The FastAPI application crashed on boot because `main.py` tried to 
     manually write token credentials directly into attributes of `modal.config._profile` 
     which modern Modal versions return as a simple string representing the profile name 
     rather than an active configuration object, throwing `AttributeError`.
   - The Resolution: Removed the manual profile assignment. Since Cloud Run natively 
     maps GCP secrets to process environment variables before execution, the Modal SDK 
     natively picks up the variables `MODAL_TOKEN_ID` and `MODAL_TOKEN_SECRET` on import.

F. The Vertex AI Prediction 404 access lock
   - The Hurdle: Calling any Gemini models (including standard `gemini-1.5-flash` or 
     `gemini-1.5-pro` in `/locations/us-central1` or `/locations/global`) returned a 
     `404 NOT_FOUND` stating the publisher model was not found or the project lacks 
     access, even though the service account had full `roles/aiplatform.user` bindings. 
     This is due to a Model Garden access restriction placed on new/individual projects 
     which requires manually accepting model terms in the GCP Console before use.
