**Error 4 — Modal .remote() calls are blocking in async FastAPI**
`storage.py` calls `_append_eval.remote(record)` which is synchronous. Inside an `async def` FastAPI endpoint this blocks the event loop. The fix is wrapping every `.remote()` in `asyncio.get_event_loop().run_in_executor(None, fn)`. None of the plans caught this.

**Error 5 — Serverless RAG corpus creation script uses `vertexai.preview`**

**Error 6 — No Modal authentication in Cloud Run**
`storage.py` calls `modal.Function.lookup()` at module import time. Cloud Run doesn't have your Modal token unless it's injected via Secret Manager. Phase 6 stores `modal-token-id` and `modal-token-secret` but `storage.py` never reads them — Modal CLI auth isn't the same as SDK auth in a container. You need to call `modal.config.set_credentials()` at startup using the env vars.

**Error 7 — The protected `query.py` in the ZIP still imports from `services.oracle`**

async def _remote(fn, *args):

async def store_interaction(...) -> str:

## Additions to Make This World-Class

These are gaps in all three plans that a senior Toptal reviewer would notice:

**1. Provenance chain is incomplete**

Right now `provenance_hash = sha256(question + answer + context)`. This is good but doesn't chain. Add a session-level merkle-style chain: each interaction's hash includes the previous interaction's hash. This means you can prove the entire session wasn't tampered with retroactively. One additional field in the eval record, three lines of code, extraordinary story for reviewers.

```python
# In eval_judge.py judge():
prev_hash = session_cache.get(f"last_hash:{session_id}", "genesis")
provenance_hash = hashlib.sha256(
    (prev_hash + question + answer + context_block).encode()
).hexdigest()[:16]
# Store for next call
session_cache[f"last_hash:{session_id}"] = provenance_hash
```

**2. Eval verdict explanation is missing from the API response**

The `EvalResult` schema has `faithfulness_score`, `verdict`, `adversarial_challenge` — but not `reasoning`. The Flash judge prompt generates `reasoning` but it's discarded before storage. Keep it. Toptal reviewers reading the API response will see a system that explains its own judgments, not just emits scores.

**3. The redline endpoint has no persistence**

`/risk` stores to Modal. `/query` stores to Modal. `/redline` generates a result and returns it, gone. Add a `store_redline()` function and call it. This makes the eval dashboard complete — you can show risk scores, query history, AND redline history. Three panels of data on one dashboard.

**4. Add a `GET /docs/registry` endpoint**

Right now documents are ingested but there's no way to list what's in the corpus. A simple endpoint returning `get_docs()` from storage takes 10 lines and makes the frontend feel like a real product — users can see what they've uploaded. Currently the frontend has no confirmation that ingestion succeeded beyond polling job status.

**5. The adversarial challenge needs a severity tier**

Right now the challenge is a string. Add a `challenge_severity: "LOW|MEDIUM|HIGH"` field to the Flash judge prompt and schema. This lets the frontend show a warning icon on MEDIUM/HIGH challenges and makes the eval dashboard scannable. The prompt addition is two sentences; the story impact is significant — it goes from "here's a challenge" to "here's how serious this challenge is."
